# Auditoría técnica ServContable PRO — septiembre 2026

Auditoría de solo lectura realizada el 18-09-2026 sobre el snapshot de distribución y verificada contra `main` (commit `4a7a44b`). Las referencias `archivo:línea` corresponden al snapshot; en `main` pueden variar algunas líneas, pero cada hallazgo marcado **VIGENTE** fue confirmado en el código actual.

## Resumen ejecutivo

ServContable PRO es un sistema contable y de remuneraciones chileno: frontend React 19 + Vite, API Node/Express 5, PostgreSQL. No usa Firebase. Producción corre en Render (`servcontablepro-api`, `servcontablepro-db`), la landing en Cloudflare Pages (`servcontablepro-web`).

Cobertura funcional amplia (plan de cuentas, comprobantes, libros, balances, ventas, compras, boletas, importación SII, IVA/F29, honorarios, pagos y cobros, conciliación, remuneraciones, Previred, finiquitos, vacaciones, auditoría, usuarios, trial, suscripciones, Flow). Código consistente, SQL 100 % parametrizado, transacciones en operaciones clave, baja lógica por `estado`.

Problemas principales: aislamiento entre empresas con huecos concretos, escalamiento de privilegios, esquema de base de datos no versionado con DDL en tiempo de ejecución, importaciones no idempotentes que informan éxito sin guardar, errores de integridad contable, sin rate limiting ni cabeceras de seguridad, sin tests.

## Stack

- Backend: Node 20+, CommonJS, Express 5.2, pg 8.21, jsonwebtoken 9, bcryptjs 3, multer 2.1, csv-parse 6.2, nodemailer 8, pdf-parse 2.4. Sin TypeScript, lint, tests, validación de esquemas, helmet ni rate limiter.
- Frontend: React 19, Vite 8, jsPDF + autotable, SheetJS. Sin router: máquina de estados `selectorModulo → selectorEmpresa → selectorEjercicio → panel` en `sessionStorage`. Token JWT en `sessionStorage`.
- Identidad visual: tokens CSS `--sc-*` (primary `#0f4c81`, cyan `#13a8e8`, teal `#10b981`, ink `#0f172a`, fondo `#f3f8fc`), Arial 13 px, componentes `sc-btn`, `sc-card`, `sc-module-card`, `sc-session-bar`, `sc-form-grid`, `sc-empty-state`, `sc-message`. Un breakpoint a 780 px.
- Base de datos: PostgreSQL 18 en Render. Esquema implícito (~30 tablas) creado con `CREATE/ALTER ... IF NOT EXISTS` desde 16 archivos del backend.
- Externos: Flow.cl (pagos), SMTP (contacto, recuperación de contraseña, invitaciones).

## Arquitectura actual

```
Navegador (React SPA, Bearer JWT)
  → Express 5 (cors, express.json, verificarToken + validarAccesoSuscripcion, demo.middleware, multer)
     → 41 routers → 41 controllers con SQL directo (pg.Pool)
        → PostgreSQL
  Externos: Flow (checkout/webhook/retorno), SMTP
```

## Qué está bien (conservar)

- SQL parametrizado en todas las consultas; no se encontró inyección SQL.
- Modelo de membresía `usuarios_empresas` con `rol_empresa` y `activo`: base correcta para multi-tenant.
- Filtro por `empresa_id` en la gran mayoría de consultas.
- Baja lógica por `estado`; solo tres `DELETE` físicos.
- Transacciones y `FOR UPDATE` en comprobantes, anulaciones, pagos, finiquitos, usuarios, empresas.
- Auditoría con helper reutilizable; historial de suscripción y auditoría de admin.
- Recuperación de contraseña con token hasheado, expiración, invalidación y correo real.
- bcrypt, CORS con allowlist, validación de variables en producción, `JWT_SECRET` mínimo 32 caracteres.
- Middleware de suscripción con respuesta `402` y whitelist para renovar.
- Generación automática de asientos desde documentos.
- Frontend: token en `sessionStorage`, `noopener`, sin `dangerouslySetInnerHTML` propio.

## Evaluación como ERP

Presente: empresas, usuarios, membresías, plan de cuentas, asientos con partida doble, documentos, pagos, remuneraciones, auditoría básica, suscripciones. Ausente o simulado: roles granulares, períodos que bloqueen, proveedores y clientes como entidad, centros de costo como catálogo, adjuntos, reversas, versionado de asientos, idempotencia, precisión monetaria.

## Plataforma

Decisión: mantener Render + PostgreSQL. Firebase no aporta beneficio para un monolito Express relacional y exigiría reescritura o Cloud SQL pagado. Ver `docs/PLAN.md`.
